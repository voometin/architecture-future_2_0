# Исходные цели:

- Промежуточное состояние (через пару месяцев). Сформировано архитектурное решение по трансформации. Уточнены границы доменов и связи между ними. Запланированы конкретные проекты в доменах по развитию «витрины данных».
- Финальное состояние (через год). Реализован портал самообслуживания. Бизнес-пользователи в доменах могут использовать данные в рамках новой архитектуры. На этом этапе можно на некоторое время сохранить легаси-системы в отдельных доменах.

# Этапы роудмапа:

Для того, чтобы достичь поставленных целей было принято решение реализовать подход Data Mesh. Для этого был составлен роудмап со следующими шагами:

Q1:
- На первом этапе необходимо разделить бизнес на домены с data-продуктами и определить границы доменов.
- На следующем этапе команда Управления данными будет настраивать DataLake и DWH для хранения (не-/полу-/-)структурированных данных. Параллельно другие команды в рамках собственных доменов будут настраивать PostgreSQL и Minio для хренения/обработки данных в рамках своих собственных доменов.
- Для каждого data-продукта определяется ответственный за качество данных (Product owner) и обеспеспечение безопасности данных.
- Также в рамках Q1 команда Управления данными будет настравить, развертывать и тестировать Airflow для последующего написания ETL/ELT пайплайнов.

Q2:
- На следующем этапе команда управления данных будет настраивать, развертывать и тестировать DataHub для формирования "супермаркета" данных.
- Параллельно команды доменов ИИ-сервисы, Медицинские услуги, Финтех, Внутренние сервисы будут писать ETL/ELT пайплайны на Airflow для загрузки данных в DataLakehouse для последующего формирования витрин данных.
- Команда BI будет заниматься интеграцией Power BI с DataHub для формирования отчетов.

Q3:
- На следующем этапе происходит тестирование и отказ различных доменов от legacy систем - MS SQL - происходит каждой командой в рамках своего собственного домена.
- В рамках отказа от старой шины данных происходит настройка, развертывание и тестирование Kafka командой управления данных.
- Начинается миграция со старой шины данных на Kafka в рамках каждого домена.
